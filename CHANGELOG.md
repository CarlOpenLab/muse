## 0.4.1

- **The v0.4.0 release is republished with its binaries.** The publish step's `files: release-assets/*` matched only the three per-platform directories, because `merge-multiple: true` downloads every artifact into that one directory and a single `*` does not cross a `/`; the action then filters the glob result with `isFile()`, so every match fell away and the release went out as an empty shell — `🤔 Pattern 'release-assets/*' does not match any files` — with the macOS DMG, `Muse.exe` and the `.deb`/`.rpm`/`.tar.gz` never attached. Widening the glob to `**/*` reaches the files, but it also drags in the `.app` bundle's internals, icons and a PKGBUILD, and the three platforms each ship a same-named `icon.png`, `icon.icns` and `update-public-key.txt`, which the action's default `overwrite_files: true` makes clobber each other until the publish fails outright. The pattern now names only what the builds really produce — the macOS DMG, the Linux `.deb`/`.rpm`/`.tar.gz` and Windows' `Muse.exe` — which is both a clean release page and no name collisions, since an installer's name is unique per platform. Naming them also means naming no extension a build does not emit: mygo produces no `.msi` and no `.pkg`, and the Windows job passes `-skip-installer` because the runner has no NSIS, so a `.msi` pattern is a dead one that `fail_on_unmatched_files: true` turns into a red publish instead of a warning — which is how the first republish failed. `fail_on_unmatched_files: true` itself turns a silent empty release into a red build. A new `internal/release` test rebuilds the exact merged directory the publish job globs over, from the file list of the real artifacts, and asserts every half: that every platform's installer reaches the release, that nothing but an installer does, that no two attached files share a name, and that every pattern matches something. / **v0.4.0 重新发布，这次带上了二进制文件。** 发布步骤的 `files: release-assets/*` 只匹配到三个平台各自的目录：`merge-multiple: true` 把每个 artifact 都下到同一个 `release-assets/` 里，而单个 `*` 不跨 `/`；action 再用 `isFile()` 过滤 glob 结果，匹配到的目录全部落空，release 于是发成一个空壳——日志里只有 `🤔 Pattern 'release-assets/*' does not match any files`——macOS 的 DMG、`Muse.exe` 与 `.deb`/`.rpm`/`.tar.gz` 一个都没挂上。改成 `**/*` 确实能穿到文件，但也会把 `.app` bundle 的内部文件、图标和 PKGBUILD 一起挂上去，而且三个平台各自都带一份同名的 `icon.png`、`icon.icns`、`update-public-key.txt`，action 默认 `overwrite_files: true`，同名文件互相覆盖，直到发布直接失败。现在模式只列构建真正产出的东西——macOS 的 DMG、Linux 的 `.deb`/`.rpm`/`.tar.gz` 与 Windows 的 `Muse.exe`——release 页面干净，同名冲突也根本不发生：安装包的名字每个平台都不一样。只列真实产物，也就不会列到构建不出的扩展名上：mygo 不产 `.msi`，也不产 `.pkg`，而 Windows 任务因为 runner 上没有 NSIS 还带着 `-skip-installer`，所以 `*.msi` 是个死模式，配上 `fail_on_unmatched_files: true` 就从一句 warn 变成一次发不出去的发布——第一次重发就是这样红的。`fail_on_unmatched_files: true` 本身则把「静默的空 release」变成一次报红的构建。新增的 `internal/release` 测试按真实 artifact 的文件清单，重建发布任务实际 glob 的那棵合并目录，逐条断言：每个平台的安装包都能挂上去、挂上去的只能是安装包、挂上去的文件不能同名、每个模式都匹配得到文件。

- The hint tests measure the hint instead of the pixels it lands on. The title placeholder's test counted rows of dark pixels, which needs a font on the machine that can draw Han characters: CI's Linux runner installs none (only `fonts-noto-color-emoji`), so Pango returns no bitmap for 标题 and the test failed there while the editor was correct. The hint's shaping is now a named function, `hintLayout`, and the tests assert on the line height it computes — 45.36px for the title's, 28px for the body's — which is the same on every machine. The body placeholder gains a test of its own, so neither can drift into the other's size. / 提示的测试改为量提示本身，而不是它落在屏幕上的像素。标题占位的测试此前数的是「暗像素的行数」，这要求机器上装着能画汉字的字体：CI 的 Linux runner 一个都没装（只有 `fonts-noto-color-emoji`），Pango 于是不给「标题」出位图，测试就在那里失败——而编辑器本身是对的。现在把提示的排版提成具名函数 `hintLayout`，测试断言它算出的行高——标题的 45.36px、正文的 28px——这在每台机器上都一样。正文占位符也有了属于自己的测试，两者谁都不会慢慢长成对方的字号。

## 0.4.0

- The editor card is now an acrylic surface you can see the desktop through: its fill is the theme's card color at an opacity you choose, with the window's material (none / weak / medium / strong — Vibrancy sidebar, popover or acrylic) behind it, and the card's left edge drags to narrow or widen it against a panel that stays exactly where it was, so the material shows through the gap that opens between them. A double click puts the card back to following the panel. All three preferences take effect at once and persist to `appearance.json`. The card keeps `cardMinWidth` of room at its narrowest, and a drag tracks the pointer instead of sticking at a clamp. / 编辑卡片现在是能透出桌面的亚克力表面：底色是主题卡片色乘一个可调的不透明度，背后是窗口材料（无 / 弱 / 中 / 强，对应 Vibrancy 的 sidebar、popover 与 acrylic），卡片左边缘可拖动以改变卡片宽度，面板原地不动，两者之间裂开的缝透出材料。双击复位，卡片重新跟随面板。三项设置即时生效并落盘到 `appearance.json`。卡片最窄时仍保留 `cardMinWidth`；拖动一路跟手，不会在中途被钳住不动。

- The card follows Beacon exactly on the one thing it lets you change: opacity only. The card color itself is fixed by the theme's palette, because an editor is a surface you read on for a long time and its contrast should not be something a user has to get right by hand. The range is clamped to `[0.30, 1]` — the same floor Beacon uses, below which the body text no longer has enough contrast against the material behind it. / 卡片在唯一开放的一项上完全照 beacon：只调不透明度。颜色本身由主题色板定死——编辑器是要长时间阅读的表面，对比度不该靠用户自己调对。取值范围钳在 `[0.30, 1]`，与 beacon 同一个下限，再低正文与背后材料的对比度就不够了。

- An empty Markdown document opens on a title. Its first line is a placeholder laid out as a level-one heading — grey, the size of the heading it will become — and what you type in it is stored in the file as `# 标题`, so the title survives in any other editor. Press Enter on the empty title to hand the line to the body instead; the body's own placeholder then reads 开始写作…. Typing Markdown in the title (`- `, `> `, `## `, a code fence) or pasting an image starts that block as it always did — the title never swallows a block you meant to write. Backspace on the emptied title brings its placeholder back, and an emptied document keeps the one line to write in. The first save offers the title as the file name (`周报.md`), and code files get no title. / 空的 Markdown 文档以标题开局。第一行是占位符，按一级标题的样子排版——灰字、它即将成为的标题的大小——在其中输入的内容以 `# 标题` 存进文件，换任何编辑器打开标题都还在。在空标题上按回车即可把这一行让给正文，正文的占位符随之显示「开始写作…」。在标题里输入 Markdown（`- `、`> `、`## `、代码围栏）或粘贴图片，照常生成对应的块，标题不会吞掉你本来要写的块；删空的标题按退格会取回占位符，删空的文档仍留着那一行可以继续写。第一次保存时以标题作为默认文件名（`周报.md`）；代码文件没有标题占位。

- Backspace and Delete no longer take the placeholder paragraph away. That line is not part of any structure — it exists so the caret and the placeholder have somewhere to be — so deleting it left an empty document with no paragraph at all, no caret and no hint. The bare empty line now survives; a phantom with context to merge (the end of a real block) is still discarded, as it should be. / 退格与删除不再丢掉占位符所在的那一行。那一行不属于任何结构——它只是为了让光标和占位符有地方待着——删掉它，空文档就一行都不剩，光标和提示一起消失。现在空行会保留；而删完有上下文要合成的 phantom（真实块的末尾）照旧丢弃，那是在删一个块。

- The body text sits closer to the card's edges: the default inset drops from 40 to 24 DIPs, and the column's width cap follows the card instead of a fixed 820. A card you dragged wider now writes a wider line — the room a drag opened is room the writing should use — while a card narrower than the cap still writes inside its padding as before. The cap keeps a line of prose from running off a very wide display. / 正文离卡片边缘更近：默认留白从 40 收到 24 DIP，正文列的限宽也从写死的 820 改为跟随卡片。拖宽的卡片写出更宽的一行——拖动让出的房间本就该用来写字——比限宽窄的卡片则照旧在留白内排版。限宽仍然守着超宽显示器上的一行散文不至于过长。

- Muse has a new face: the **Page Muse** icon — a soft-white page with a gold dog-ear, a nib-tapered bottom and a wink — replaces the old gradient M in every place the app and site look for it: `resources/icon.png`, `resources/icon.icns`, the website favicon and the social card. The ICNS keeps all ten representations at 516 KB — 43% smaller than the artwork's first build (898 KB) — rebuilt losslessly from pngcrush-compressed PNGs; the 1024 px master is opaque sRGB with no baked corner mask, so the platform supplies the mask. The vector source, four-size renders and the 91/100 evaluation live in `resources/logo/`. / Muse 换了新面孔：**Page Muse** 图标——奶白纸页、金色折角、收成笔尖的底边和一次眨眼——替换了应用与官网所有引用位置的旧渐变 M：`resources/icon.png`、`resources/icon.icns`、网站 favicon 与社交卡片。ICNS 保留全部十个尺寸，并用 pngcrush 无损重压的 PNG 重建，从 898 KB 降到 516 KB；1024 px 母版为不透明 sRGB，不烘焙圆角，由平台自己裁切。矢量源、四尺寸渲染与 91/100 评估记录在 `resources/logo/`。

- The official site is live at carlopenlab.github.io/muse and now describes the fully native `mdedit` canvas instead of an embedded Milkdown page: a zero-build single page that recreates the app window in DOM, plays a real Agent approval demo, and has a monochrome light/dark theme. Its metadata, hero, native section, README, favicon and social card are updated. / 官网已上线 carlopenlab.github.io/muse，并把「内嵌 Milkdown 画布」改为全原生 `mdedit` 画布：零构建单页用 DOM 复刻应用窗口、播放真实的 Agent 审批演示，支持黑白双主题；元信息、首屏、原生章节、README、favicon 与社交卡片一并更新。

- The AI panel is now a writing Agent: 13 document tools, approval cards for edits (同意修改 / 总是允许 / 拒绝), three permission presets (每次询问 / 完全访问 / 只读), a reworked composer, and recent files in the empty state; settings group the tools by capability. / AI 面板升级为写作 Agent：13 个文档工具、修改前的审批卡（同意修改 / 总是允许 / 拒绝）、三档权限预设（每次询问 / 完全访问 / 只读）、重排的输入区与空态最近文件；设置里按能力组开关工具。

- Large documents open fast: the editor parses incrementally, re-parses only the lines an edit touches, and lays out only what shows; the first frame of the large fixture went from about 1.6 s to about 20 ms. / 大文档打开更快：编辑器增量解析，只重算改动触及的行，排版只处理可见部分；大文档首帧从约 1.6s 降到约 20ms。

- macOS updates keep their permission grants: the DMG is signed with a stable Apple Development identity, so TCC approvals survive a version change. / macOS 更新保留授权：DMG 用固定的 Apple Development 身份签名，TCC 授权跨版本沿用。

- A closing tag of block HTML on a line of its own no longer shows as text. A blank line before `</details>` makes the tag a block of its own to CommonMark, and the editor drew that block's source because its display was empty and the layout fell back to the raw lines; a block that reads as nothing is now left out of the page — no text and no gap — and still shows its source when the caret enters it, as the tags around it do. Pinned by a regression test and an assertion over the all-syntax fixture. / 单独成行的块级 HTML 闭合标签不再显示成文字。`</details>` 前有空行时，按 CommonMark 它是一个独立的块；它的显示为空，布局便退回原样画出源码。现在「读不出内容」的 HTML 块在页面里完全不占位——不显示文字也不留空隙——光标进入时仍显示源码，与它周围的标签一致。有回归测试与 all-syntax 文档的断言把守。

- The CommonMark 0.31.2 spec's 652 examples (`testdata/commonmark/spec.json`) now drive both parsers. `mdoc` checks that every parser block survives as a model block of a kind the source can produce; the editor's engine (`mdedit/spec_test.go`) must render exactly the spec's reference HTML with no extensions — 652/652 — while the five examples where GFM's linkify intentionally adds links are pinned as the only GFM difference, and the escaped-bracket examples show their text rather than a formula. Focused tests cover headings, breaks, quotes, lists, code, HTML, tables, images, emphasis, links, escapes, line breaks and math; the editor gets an `all-syntax.md` fixture rendered end to end. The tests found and fixed three model bugs: `~~strikethrough~~` kept its text but lost its style, e-mail autolinks lost their `mailto:` target, and footnotes (`[^1]`) parsed as link definitions, so `mdoc` silently dropped the definition's text — footnotes now use goldmark's extension and appear as `[n]` items. Headless tests no longer render while the agent goroutine edits the same app (a frame lock), and `nativeui` tests use a throwaway config directory instead of the developer's real `chat.json`. The Electron-era leftovers (~723 MB: `editor-web/`, `app/`, `node_modules/`, `native/embed/` and the pnpm files) are gone; the repository is Go only, runtime and build alike. / CommonMark 0.31.2 规范的 652 个用例（`testdata/commonmark/spec.json`）现在同时驱动两套解析器：`mdoc` 检查解析器的每个块都保留为模型里对应种类的块；编辑器的解析引擎（`mdedit/spec_test.go`）在不加扩展时必须逐字呈现规范的参考 HTML——652/652——GFM 仅有的 5 个「linkify 主动加链接」用例被固定为唯一差异，转义方括号的用例显示的也是文字而非公式。另有标题、分隔线、引用、列表、代码、HTML、表格、图片、强调、链接、转义、换行与公式的分类测试；编辑器新增 `all-syntax.md` 全语法文档做端到端渲染测试。测试查出并修掉三个模型缺陷：`~~删除线~~` 只留文字丢了样式、邮箱自动链接丢了 `mailto:`、脚注（`[^1]`）被当成引用链接定义导致定义正文在模型里消失——脚注改用 goldmark 的扩展解析，并以 `[n]` 列表项出现在模型里。headless 测试不再在 Agent goroutine 修改同一份 App 状态时渲染（加了帧锁），`nativeui` 测试也改用自己的临时配置目录，不再读开发机真实的 `chat.json`。Electron 时代的残留（约 723MB 的 `editor-web/`、`app/`、`node_modules/`、`native/embed/` 与 pnpm 文件）已删除，仓库从此只剩 Go，运行时与构建都是。

- The editor is fully native again, and Typora-like: the WebView canvas (Vue 3 + Milkdown in MyGo's WebView element, `editor-web/`, `nativeui/web/dist`, `webeditor.go` and its bridge) and the old block-at-a-time fallback (`wysiwyg.go`, `blocks.go`, `image_edit.go`, `code_edit.go`, `syntax.go`) are gone, replaced by `native/mdedit`: one surface the whole document is written on, drawn by MyGo. The Markdown source is its only state — the caret, selections, undo and the input method all work on source offsets — and it is parsed with MyGo's CommonMark/GFM parser, which keeps the offsets of every block and inline. Block syntax (`#`, list markers, `>`, fences, pipes) never shows; inline syntax (`**`, `` ` ``, `[]()`, `$`, `![]()`) shows in gray only around the caret, as Typora does. Markdown shortcuts work as typed (```` ``` ```` and `$$` open closed blocks at once, `| a | b |` + Enter makes a table); Enter, Backspace, Delete and Tab follow Typora in paragraphs, headings, lists, task lists, quotes, code and tables; images render inline or as blocks (pasted and dropped images are saved into `assets/`), math is typeset on the text's baseline, Mermaid diagrams draw natively, code is highlighted with the code editor's lexers (30+ languages), and text files that are not Markdown open as highlighted code. The agent's edits go through the editor as steps of undo. MyGo goes from v0.4.5 to v0.7.3 for the parser, inline objects in text layouts and painting only what shows. The search panel gains replace, the outline follows the caret, and the menu bar gains 段落 and 格式 menus. Math typesetting no longer cuts formulas off: rasters are sized by the ink of what go-latex draws, and the script fallback (as for `\int_0^1`) composes its parts on one baseline. / 编辑器回到全原生，并对齐 Typora：移除 WebView 画布（MyGo WebView 元素里的 Vue 3 + Milkdown、`editor-web/`、`nativeui/web/dist`、`webeditor.go` 及其桥）和旧的逐块回退编辑器（`wysiwyg.go`、`blocks.go`、`image_edit.go`、`code_edit.go`、`syntax.go`），由 `native/mdedit` 取代：整篇文档一面可写的画布，由 MyGo 绘制。Markdown 源码是唯一状态——光标、选区、撤销与输入法都作用于源码偏移——解析用 MyGo 的 CommonMark/GFM 解析器，它保留每个块与行内元素的源码区间。块级语法（`#`、列表符号、`>`、围栏、表格竖线）从不显示；行内语法（`**`、`` ` ``、`[]()`、`$`、`![]()`）只在光标周围以灰色显露，与 Typora 一致。Markdown 快捷输入即打即生效（```` ``` ```` 与 `$$` 立即生成带闭合的块，`| a | b |` 回车生成表格）；回车、退格、删除与 Tab 在段落、标题、列表、任务、引用、代码与表格里都按 Typora 的语义；图片行内或成块渲染（粘贴、拖入的图片存进 `assets/`），公式与正文基线对齐，Mermaid 原生绘制，代码用代码编辑器的词法高亮（30+ 语言），非 Markdown 文本文件以带高亮的代码打开。Agent 的修改经编辑器写入，可以撤销。MyGo 由 v0.4.5 升级到 v0.7.3（解析器、文本布局里的行内对象、只绘制可见部分）。搜索面板新增替换，大纲跟随光标，菜单栏新增「段落」「格式」。公式排版不再被截断：位图按 go-latex 实际绘制的墨迹定大小，脚本回退路径（如 `\int_0^1`）在同一基线上组合各部分。

- The shell borrows Beacon's frame: on Windows and Linux the system's window buttons are gone and the view draws Windows 11's own — minimize, maximize or restore and close as three flat glyphs on the editor header's line, the close one turning red under the pointer, the maximize one bringing the snap layouts.
