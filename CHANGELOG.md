# Changelog

## Unreleased

- Files panel: dedicated 全部折叠 (collapse-all) button at the top-right of the toolbar, and a double-click on a folder no longer net-collapses (second click within 300ms is ignored). Outline redesigned: level-sized type (H1 semibold → deep levels muted), a 2.5px accent bar marks the active heading instead of a full-row block, hover row highlight, tighter 26px rows. / 文件面板：工具栏右上加「全部折叠」按钮；双击文件夹不再表现为展开又折叠（300ms 内的第二次点击忽略）。大纲重设计：标题按层级定字号（H1 半粗 → 深层弱化为灰字），活动行用 2.5px 强调色竖条替代整行大色块，悬停高亮，26px 紧凑行高。

- Fix theme desync for real: the rail toggle sent the canvas the OLD theme because a.dark is only derived during the view rebuild — the canvas lagged one toggle behind the shell. webThemeName now derives from themeMode (0 light / 1 dark) at call time. / 真正修掉主题不同步：侧栏切换瞬间 a.dark 还没随视图重建刷新，画布收到的是旧主题、永远慢一拍；webThemeName 改为按 themeMode（0 浅 / 1 深）即时推导。

- Fix: theme.set reached the canvas but only flipped a local flag — the prose colors never moved because tokens were applied in the PoC shell, not the Vue app. The canvas now applies theme tokens (CSS vars on :root) on every theme.set/document.set, verified light/dark both ways. / 修复：theme.set 到达画布后只翻了本地标记——token 应用留在 PoC 壳里没进 Vue 应用，正文配色纹丝不动。现在每次 theme.set/document.set 都应用主题 token（:root CSS 变量），明暗双向验证通过。

- Fix: a file whose last block is not a paragraph (e.g. a title-only document — Markdown parsing drops the trailing blank line) had no body slot at all, so clicking below the title did nothing. The canvas now keeps a trailing editable paragraph (Typora-style), so the body placeholder shows and clicking below the title just works. / 修复：末块不是段落的文档（如只有标题的文件——Markdown 解析会吞掉尾部空行）没有正文位，标题下方点不出光标。画布现在始终保留末尾可编辑段落（Typora 式），正文占位照常显示，标题下直接点击即可输入。

- The files-panel new actions are icon-only squares (tooltip on hover), matching the rail's visual language. A headless regression test walks the full chain: toolbar click → 未命名.md created empty → auto-opened, and 新建文件夹 likewise. / 文件面板新建动作改为纯图标方块（悬停出提示），与侧栏视觉一致。新增无头回归测试走通整条链：点击 → 未命名.md 空文件落盘 → 自动打开，新建文件夹同理。

- The left rail is now module switching only (文件/大纲/搜索/AI + theme/settings): 新建 and 打开文件夹 leave the rail — new-file/folder live in the files panel toolbar, opening lives in the files panel empty state, and ⌘N/⌘O/⇧⌘O stay in the menu. / 最左侧栏只保留模块切换（文件/大纲/搜索/AI + 主题/设置）：移除「新建」「打开文件夹」——新建类动作在文件面板顶部工具栏，打开类在文件面板空态，菜单 ⌘N/⌘O/⇧⌘O 不变。

- New file / new folder move into the files panel as a visible toolbar row at the top of the list content (Obsidian's explorer-header way), instead of hiding in the drag header; they create into the selected folder when one is selected, else the workspace root. / 「新建文件 / 新建文件夹」并入文件面板，在列表内容顶部以工具栏成排展示（Obsidian 资源管理器头部方式），不再藏在拖拽头里；选中文件夹时在其中创建，否则落在根目录。

- Independent placeholders for the title and body slots (Typora-style): a blank document is a real two-slot template — empty heading shows 写下标题… while the empty paragraph below shows 在此落笔… at the same time, each caret-independent; after the title has text the body hint becomes 继续书写…. A never-typed document serializes to "" so files stay clean, and new documents/files are created empty on the host to match. / 标题位与正文位独立占位（Typora 式）：空文档是真实的双槽模板——空标题显示「写下标题…」，其下空段落同时显示「在此落笔…」，光标互不相干；标题有字后正文提示变「继续书写…」。从未输入过的文档序列化为 ""，存盘干净；宿主侧新建文档/文件也改为真空内容与之配合。

- Rail declutter: the redundant 打开文件 button is gone (⌘O and the files panel empty state cover it — the empty state now offers 或打开单个文件), and a hairline divider separates the action group (新建 / 打开文件夹) from the view group (文件 / 大纲 / 搜索 / AI). / 侧栏精简：移除重复的「打开文件」按钮（⌘O 与文件面板空态覆盖——空态新增「或打开单个文件」入口），动作组（新建 / 打开文件夹）与视图组（文件 / 大纲 / 搜索 / AI）之间加一条细线分隔。

- Placeholders for empty content in the web canvas: an empty document shows 在此落笔… in muted gray, an empty heading shows 写下标题…, and a trailing empty paragraph after existing content shows 继续书写… (mid-document blank lines stay clean). Node decorations + CSS ::before, so the caret rests on the hint and typing replaces it; the empty heading created by the "# " input rule keeps the heading hint, not the body's. / WebView 画布空内容占位符：整篇为空显示灰字「在此落笔…」，空标题显示「写下标题…」，已有内容后末尾的空段显示「继续书写…」（中途空行不打扰）。node decoration + CSS ::before 实现，光标停在占位符上，输入即替换；"# " 输入规则产生的空标题保留标题提示而不误用正文提示。

- Ship the WebView canvas (RFC-001 target architecture): the document surface is now a Vue 3 + Milkdown/ProseMirror page hosted by MyGo's own `ui.WebView` element — rendering and editing are one representation, so the native route's click-time height jitter and flash cannot occur by construction. Verified end-to-end: 13/13 vitest (protocol + mygo transport), browser e2e shows zero block movement clicking h1/h2/li and typing, and the Linux build renders the host-pushed document in WebKitGTK. / 落地 WebView 画布（RFC-001 目标方案）：正文改为 MyGo 自带 `ui.WebView` 承载的 Vue 3 + Milkdown/ProseMirror 页面——渲染与编辑是同一表示，原生路线的点击跳动/闪烁从构造上不可能发生。页面由 embed.FS 构建随二进制分发（`editor-web/` → `native/nativeui/web/dist`），经 mygo IPC 跑 RFC-001 §5.2 协议（`Muse.*` 绑定方法 + `muse:bridge` 事件、200ms 防抖、双端 revision 守卫），保存向画布索取最新内容，Web 引擎缺失或 `MUSE_NATIVE_EDITOR=1` 自动回退全原生编辑器。已验证：13/13 vitest（协议 + mygo 传输层）、浏览器 E2E 点击 h1/h2/li 与打字全部零位移、Linux 构建在 WebKitGTK 中渲染宿主推送的文档。
